## Candidate capability areas

**Layout SDK** (`packages/sdk`): owns layout primitives and their native layout CSS — `Stack` (`padding`, `flex`), `Text`, `Separator`, `Spacer`, `Scroll`, `Wrap`, `Grid` (`columns` 2|3|4). `Image` remains in `packages/sdk` but is unregistered: the MCP App CSP allows only `'self'` and `data:` for `img-src`, so a remote `src` cannot load. Overlay/`ZStack` only if a later case needs absolute layering. Centering is `Stack` align/justify, not a type. Do not implement these by wrapping `common/ui`. Do not use Tailwind utilities or CVA in the SDK.

**Common styled controls** (`packages/common`):
- `ui/` — full shadcn/Base UI host substrate (owned source under `src/ui`). Keep the catalog complete so authors reuse it instead of inventing parallel controls. Not Engawa-registered.
- `components/` — finite agent-facing wrappers registered into Engawa today: `Button`, `Card`, `Checkbox`, `DataGrid`, `Label`, `Progress`, `Rating`. Expose further `ui` controls here one-by-one when an acceptance case needs them.
- Tailwind classes in `packages/common` only exist if their directory is listed in `src/styles.css` via `@source`. The package loads through a `node_modules` symlink, which Tailwind's automatic detection skips. A class used in exactly one `components/` wrapper is the case that silently disappears; confirm new utility usage by grepping the built `mcp/dist/app.html` for the generated rule, not by checking that the className is emitted.
- Icons: `lucide-react` is the settled internal glyph source (already used by 23 `ui` components). A component that needs a glyph owns it internally, as `Rating` owns its star; do not wait on the deferred public `Icon` catalog and do not add a second icon library.
- `Rating` is display-only (`value`, `max`), fills partial stars via a clipped overlay, and uses theme foreground/muted rather than amber so it follows host light/dark. An interactive rating belongs in a form, not a grid cell.
- `DataGrid` baseline (verified 2026-09-11 on the Cube Attain `/visualize` seed): thin `data` (+ optional `columns`) map over shadcn `ui/table`. `columns` may be key strings or `{ key, label, type, format }` objects, where `type` is `text | number | boolean | date` and `format` passes `Intl` options through in the viewer's locale. Types infer from the first non-null value except `date`. A cell may also be a `{ children, value }` envelope: `children` renders a node in that cell, `value` keeps the datum so the column's type, format, and later sorting stay meaningful. Document nested prop shapes in the owning prop's TSDoc—the loader reads only the component's own props, so nested TSDoc never reaches the agent. Improve from that floor; do not reopen the multi-node table family.
- Node-bearing props generally: `render` hydrates any serialized node found inside a prop value, recognized structurally (keys within `type`/`props`/`children`, `type` registered) by one test shared with the validator. A component reading such a prop should tolerate both spellings and degrade to a plain value rather than handing React an object. A top-level slot prop is any prop whose type accepts a React element: the metadata loader records it as the `node` kind and the tool contract advertises it as `string | Node | Array<string | Node>`. `Card` declares its slots as `ReactNode | SerializedNode | Array<…>` locally, so `Tree<typeof components>` accepts the serialized spelling without `packages/common` depending on `packages/engawa`, and renders a slot value it cannot hydrate as nothing. When sorting, selection, column resize, wrapping, or virtualization become acceptance needs, prefer composing a headless grid (TanStack Table now; Base UI Data Grid if/when it ships — [base-ui#3328](https://github.com/mui/base-ui/issues/3328)) under `ui`/`components` rather than growing bespoke grid logic in the agent wrapper.

The MCP registry is **sdk + common** for Better Response. Do not put styled controls into `packages/sdk`. Agents must not pass `style` or `className`.

Controls next (as common agent wrappers): `RadioGroup` + `Radio`, `Accordion`, `Tabs`, `Alert`, `List` + `ListItem`.
`List`/`ListItem` are substrate-styled (markers, indent, row chrome), not SDK layout; a `Stack` of `Text` is already the unstyled list.
Later only if forced: named `Icon`, `Link`, `Switch`, `Select`. Keep free-form `Input` / `Textarea` out until agent-connected interaction is in scope.
`Card` is registered as one component with `media`, `title`, `description`, `action`, and `footer` slots and `children` as body; it is chrome with slots, not an outcome shape. Badge stays `ui` only unless a later acceptance proves an agent contract is required.
